# Web: shell, design system, plugin frontends

Bun workspaces at the repo root: `web` (`@arena/shell`), `platform/design` (`@arena/design`), `plugins/*/frontend` (`@arena/<plugin>`, 21 of them).

```
bun install                      # at the repo root; site.sh uses --frozen-lockfile
cd web && bun run build          # gen-plugins, gen-tokens, tsc, vite build -> web/dist
cd web && bun run dev            # vite dev server
bun test                         # at the repo root (a whole-suite run waits for a free slot on the host)
bun run typecheck                # at the repo root: web, design, plugins, scripts, tests, slot type checks
```

## Layout

| Path | What |
|---|---|
| `web/src/main.tsx` | Entry: loads styles, calls `mountApp(root, plugins)`. |
| `web/src/shell/` | `@arena/shell`: router, frame, slots, widgets, page events, `t()`, `api()`, session. |
| `web/src/plugins.gen.ts` | Generated by `scripts/gen-plugins.ts` from `plugins/*/plugin.toml`. Committed; a test fails when stale. |
| `platform/design/` | `@arena/design`: tokens, fonts, base and KOL Arena pieces. |
| `platform/design/src/tokens.css` | Generated by `scripts/gen-tokens.ts` from the front matter of `DESIGN.md`. Committed; a test fails when stale. |
| `plugins/<name>/frontend/` | One package per plugin: `src/index.ts` (`definePlugin`), `src/en.ts` (strings). |

## Writing a plugin frontend

```ts
// plugins/moves/frontend/src/index.ts
import { lazy } from "react";
import { definePlugin } from "@arena/shell";
import { dict } from "./en";
import { RankChange } from "./RankChange";

export const plugin = definePlugin({
  name: "moves",                                   // = plugin.toml name
  screens: { collection: () => import("./Collection") },   // key = plugin.toml screens[].name; lazy: its own chunk
  fills: { "board/rank_change": RankChange,        // key = "<host>/<slot>" from plugin.toml fills
           "board/ticker": lazy(() => import("./MovesTicker")) },
  widgets: { add_to_fight: AddToFight },           // plain names from plugin.toml widgets
  dict,                                            // keys all start with "moves."
});
export default plugin;
```

- `scripts/gen-plugins.ts` reads `plugin.toml`; the shell checks each plugin against its manifest at start-up (and in `bun test`). A screen, fill, widget or dictionary key that the manifest does not list is an error that names it.
- A plugin frontend imports only `react`, `@arena/design`, `@arena/shell` and its own files. `@arena/design` imports no plugin and calls no route. Both are tests.
- Every screen is a loader `() => import(...)`, so staff and admin screens are separate chunks. A staff-only filler or widget should be `lazy(...)` too. The bundle check reads `web/dist/.vite/manifest.json` (Vite `build.manifest`) to see which chunks `/`, `/kol/:id` and `/fight` load.
- Screens use design pieces only: no own colours, buttons or fonts. Every UI string goes in `en.ts`.

### Shell API (`@arena/shell`)

| Export | Use |
|---|---|
| `definePlugin({ name, screens, fills, widgets, dict })` | The plugin's one export. |
| `<Slot name props>default</Slot>` | A named place a plugin leaves open. Shows fillers in layer order, each in its own error boundary and Suspense; with no filler it shows its children. |
| `<Widget name props fallback>` | A piece another plugin offers (`fight/add_to_fight`, `fight/fighter_picker`). |
| `SlotProps<'board/rank_change'>`, `WidgetProps<...>`, `SlotName`, `WidgetName` | Typed props for every slot and widget. Ids and dates only; the filler loads its own data. |
| `usePageEvent(name, fn)`, `emitPageEvent(name, payload)` | Page events `fighter_added { kol }` and `fight_over { ids, date, winner \| null }`. |
| `t(key, vars?)` | Dictionary text. `{name}` in a text is replaced from `vars`. |
| `api(path, { method, body, signal })` | Fetch helper. Returns `{ data }` or `{ error: { status, message, code? } }`. Never throws. |
| `useApi(path)` | `{ status: 'loading' \| 'ready' \| 'error', data, error, reload }`. A `null` path loads nothing. |
| `useSession()` | `{ state, reload, signOut }`. `state` is `idle`, `loading`, `anonymous`, `ready { person }` or `error`. Calls `GET /api/auth/me`. |
| `Link`, `navigate`, `useLocation`, `useParams`, `useSearchParams` | History API routing. |
| `useOverlayClose()` | For `/kol/:id` and `/fight`: the function for the `Dialog`'s `onClose`. |
| `useTickerItems(owner, items)` | Adds items to the ticker strip at the top of the frame. Memoize `items`. |
| `ANCHORS`, `safeNext(raw)`, `LOGIN_PATH`, `TEAM_HOME` | Section anchors (`leaderboard`, `network`, `fight`, `how-it-works`), the `?next=` check for the login screen. |

### Routes

- `/` home. `/kol/:id` and `/fight` open over `/`: the home screen stays mounted and the overlay screen renders next to it. The overlay screen renders its own `Dialog` with `onClose={useOverlayClose()}`. Close goes back when the overlay was opened from the home page, and replaces the entry with `/` when it was opened by a direct link.
- `/team/login` is public. Other `/team/*` screens need a session: no session goes to `/team/login?next=<page>`; a role that the screen's tag does not allow sees "Your role cannot open this page". `/team` goes to `/team/wallets`. The team layout (menu of the six sections, a drop-down on a phone) is the shell's.
- `/team/design` is the design gallery (staff). The shell registers it, not a plugin.

### Session contract

`GET /api/auth/me` returns `{ "login": "anna", "role": "staff" | "admin", "id": 3 }` for a person with a session and `401` for nobody. A 401 from any route outside `/api/auth/` ends a ready session at once. `POST /api/auth/logout` is called by `signOut()`. The login screen (auth plugin) posts to `/api/auth/login`, calls `useSession().reload()` and then `navigate(safeNext(next))`.

## Design system

- Tokens: edit `DESIGN.md`, run `bun scripts/gen-tokens.ts` (also run by `bun run build`). Never edit `tokens.css`. Names: `--color-*`, `--type-<style>-<prop>`, `--radius-*`, `--space-*`, `--component-<name>-<prop>`; one `.t-<style>` class per type style.
- Fonts: `@fontsource/press-start-2p`, `golos-text`, `jetbrains-mono`, latin and cyrillic, served from our own files (`platform/design/src/fonts.css`). No request goes to Google.
- Pieces (all in `@arena/design`): Button, Field, Select, List, Card, StatTile, Dialog, Tabs, Badge, Progress, Tooltip, Skeleton, EmptyState, ErrorLine, Heading, Container, Logo, PixelAvatar, TierBadge, ScoreBar, NoData, Money, TimeAgo, SnapshotDate, ScoreBreakdown, Ticker, HpBar, RoundRow, Bracket; formatters `formatMoneyShort`, `formatMoneyFull`, `formatMinutesAgo`, `formatTimeAgo`, `formatSnapshotDate`.
- Pieces show what the caller passes and take every visible or spoken text as a prop. Open `/team/design` to see them all.
- A disabled `Button` needs a `reason`: it stays focusable (`aria-disabled`), does nothing on click and prints the reason beside it.

## Design gallery without a session (Playwright checks)

`/team/design` is a staff screen and `/api/auth/me` has no backend yet in a lane worktree. To look at the gallery anyway, build with the Vite env flag, **at build time only**:

```
cd web && VITE_DESIGN_GALLERY_OPEN=1 bunx vite build --outDir ../tmp/f2-dist
cd web && bunx vite preview --outDir ../tmp/f2-dist --port <free port>
```

The flag is off by default; `bun run build` and `scripts/site.sh` never set it. Do not set it for a site that clients can reach.

## Tests

`bun test` at the repo root runs: tokens equal `DESIGN.md` (and the palette contrast is 4.5:1 or better), `plugins.gen.ts` is fresh, the shell contract matches the manifests, the import rules, Money, TimeAgo and SnapshotDate formats, PixelAvatar is deterministic, every `t()` key exists in a dictionary, routing rules and `safeNext`, `api()` and session behaviour. `bun run typecheck` also compiles `web/tests/slot-types.check.tsx`, which fails when a wrong slot, filler or widget starts to compile.

# KOL Arena: архитектура системы

## 1. Введение

KOL Arena строится из бизнес-компонентов — блоков. Каждый блок — плагин: у него свои данные, экраны, маршруты и API. Блоки стоят в слоях. Блок пользуется только своим слоем и слоями ниже; вызовы и зависимости никогда не идут по кругу. Продукт берёт нужные слои; пропущенный блок работает как заглушка.

- Каждый блок входит в первую сборку. Ещё не построенный блок идёт заглушкой, выключенной для приложения, группы или человека.
- Поведение внутри блока — его реализация, не архитектура. Реализации меняются и сравниваются без правок в других блоках.
- Верхний слой добавляет к нижнему только через API, события, слоты и виджеты. Нижний слой не знает, что стоит над ним.
- [Платформа и сборка](#sec-5-платформа-и-сборка) лежат под всеми слоями; это не бизнес.

## 2. Плагины

Каждый бизнес-компонент — плагин: одна папка с постоянной структурой. Любая команда может забрать папку, собрать и проверить её отдельно, держать в своём репозитории; главный репозиторий подтягивает её по версии. Ничто не связывает два плагина, кроме их API, событий, слотов и виджетов.

```
plugins/<name>/
  plugin.toml    имя, версия, теги; API, которое даёт; API, события и слоты, которыми пользуется
  api/           типы его API для плагинов, которые его вызывают
  backend/       крейт Rust: маршруты, реализации, задачи, его SQL
  migrations/    его собственная схема базы
  frontend/      пакет React: экраны, виджеты, заполнители слотов
  stub/          реализация «выключено»: пока блок не построен или выключен приложением
  tests/         нужны только плагины, которые он вызывает, или их заглушки
```

- Плагин обращается к другому только через API, события, слоты и виджеты. Никогда — через его таблицы, файлы или код.
- Слот: именованное место, которое оставляет плагин. Заполнитель — плагин того же или более высокого слоя. Без заполнителя слот показывает своё значение по умолчанию.
- Виджет: именованный кусок экрана, который плагин отдаёт; плагин того же или более высокого слоя ставит его на свою страницу.
- Слот и виджет передают только id; заполнитель и виджет сами загружают свои данные.
- События страницы: плагины на одной странице действуют друг на друга через именованные события с постоянными полями. Ни один плагин не импортирует другой.
- Каждый вызов API несёт человека, от имени которого он идёт. На публичных страницах это никто.
- Каждый маршрут говорит, принимает ли он никого. Маршруты `public` принимают никого, и маршрут входа тоже.
- Экраны плагина пользуются только деталями [дизайн-системы](#sec-дизайн-система-даёт-каждому-экрану-его-вид).
- [Сервер](#sec-сервер-запускает-все-блоки-одной-программой) и [веб-оболочка](#sec-веб-оболочка-обрамляет-каждую-страницу) находят плагины по `plugin.toml`; настройки приложения говорят, какие плагины и теги оно берёт.
- Код: Rust (axum, sqlx) — workspace Cargo, по крейту на плагин; страница — TypeScript и React, по пакету на плагин; база Postgres, у каждого плагина своя схема.

## 3. Бизнес-компоненты

**KOL Arena: рейтинг Solana KOL по результатам кошельков, с боем KOL Fight.** Слои 0–4, каждый поверх нижних.

### 0. Общее

Нужно каждому слою.

#### Вход: пускает сотрудников в закрытый раздел

- **Что делает:** хранит сотрудников, их роли и сессии. Заполняет слот платформы «человек запроса».
  - Роли: сотрудник и администратор. Администратор добавляет сотрудников и отзывает доступ.
  - Пароли хранятся только хешем; сессия в cookie, недоступной скриптам страницы.
  - Частые неудачные входы с одного адреса временно блокируются.
  - Первый администратор создаётся из настройки сервера при первом запуске.
- <b class="arch-screens">Экраны:</b>
  - `вход` (логин и пароль) <span class="arch-tag">#public</span>. Детали: поле, кнопка.
  - `сотрудники` (список, добавить, отозвать доступ) <span class="arch-tag">#admin</span>. Детали: список, диалог.
- <b class="arch-routes">Маршруты:</b>
  - `POST /api/auth/login` (вход: логин, пароль; выход: сессия) <span class="arch-tag">#public</span>
  - `POST /api/auth/logout` (выход: пусто) <span class="arch-tag">#staff</span>
  - `GET /api/auth/me` (выход: сотрудник и роль) <span class="arch-tag">#staff</span>
  - `GET /api/admin/staff`, `POST /api/admin/staff`, `POST /api/admin/staff/:id/revoke` (сотрудники) <span class="arch-tag">#admin</span>
- <b class="arch-api">API:</b>
  - `who(session)` (вход: сессия; выход: сотрудник и роль или никто)
- **Вызывает:**
  - Журнал, чтобы записать вход, добавление и отзыв сотрудника.
- **На экранах:** [Вход](#sec-вход), [Сотрудники](#sec-сотрудники).

#### Журнал: записывает, кто что изменил

- **Что делает:** хранит записи об изменениях: кто, когда, в каком блоке, какой объект, что было и что стало. Простое хранилище: только API, без экранов и проверки прав.
- <b class="arch-screens">Экраны:</b> нет.
- <b class="arch-routes">Маршруты:</b> нет.
- <b class="arch-api">API:</b>
  - `record(person, block, object, action, before, after)` (выход: id записи)
  - `history(block, object)` (выход: записи по времени)
- **Вызывает:** никого.

### 1. Арена

Даёт клиентскую страницу, карточку KOL и бой на сохранённом снимке. Самый малый продукт, живёт сам: клиент открывает рейтинг первого снимка (данные прототипа), смотрит карточки и проводит бои.

#### Реестр KOL: хранит KOL и их публичные кошельки

- **Что делает:** хранит KOL: id, имя, хэндл X, ссылки (KOL Explorer, Solana Tracker, Kolscan, FOMO, pump.fun, Telegram, Solscan по кошельку), опубликованный основной кошелёк и другие кошельки, охват аудитории с источником и датой, форматы работы. Простое хранилище: только API.
  - Здесь только опубликованные кошельки. Гипотезы сюда не попадают.
  - Один кошелёк — у одного KOL.
  - Первый набор KOL — из данных прототипа.
- <b class="arch-screens">Экраны:</b> нет.
- <b class="arch-routes">Маршруты:</b> нет.
- <b class="arch-api">API:</b>
  - `upsert_kol(profile)` (выход: id KOL)
  - `get_kol(id)`, `list_kols(ids)` (выход: профили)
  - `find_by_handle(x)`, `find_by_wallet(address)` (выход: id KOL или ничего)
  - `publish_wallets(kol, main, others, source)` (выход: пусто; отказ, если кошелёк уже у другого KOL)
  - `set_reach(kol, reach, source, date)`, `set_formats(kol, formats)` (выход: пусто)
- **Вызывает:** никого.

#### Снимки: хранят метрики KOL по дням

- **Что делает:** хранит снимок на каждую дату: кто стоит на борде и почему, метрики каждого KOL по схеме требований (PnL за 24 часа, 7 и 30 дней, win rate за 7 и 30 дней или за всё время, средняя позиция, холд, минуты с последней сделки, нереализованный и итоговый PnL, объём, дни со сделками, сделки в плюс и в минус, место по PnL, «в топе дня»), источник и время получения каждой строки. Простое хранилище: только API.
  - Снимок открывается, наполняется и закрывается. Закрытый снимок не меняется.
  - Нет метрики — пусто, не ноль.
  - Повторный сбор за ту же дату обновляет тот же снимок, пока он открыт.
  - При закрытии участник без новых метрик получает свои последние метрики с прежними источником и временем получения. Так цифры не подменяются, а дата показывает их возраст.
  - Первый снимок — данные прототипа (17–18 октября 2026), загружаются при установке.
- <b class="arch-screens">Экраны:</b> нет.
- <b class="arch-routes">Маршруты:</b> нет.
- <b class="arch-api">API:</b>
  - `open(date)` (выход: снимок)
  - `close(date)` (выход: снимок; переносит последние метрики участникам без новых)
  - `put_metrics(date, kol, metrics, source, fetched_at)` (выход: пусто)
  - `set_member(date, kol, reason)` (выход: пусто)
  - `snapshot(date)` (выход: участники и их метрики)
  - `latest_date()`, `dates()` (выход: даты закрытых снимков)
  - `history(kol, from, to)` (выход: метрики по дням)
- **Вызывает:** никого.

#### Arena Score: считает Score, тир, значки и место

- **Что делает:** считает по формуле требований четыре части (прибыль, точность, форма, активность), Score, тир, значки и место каждого KOL снимка. Хранит итог по закрытому снимку.
  - Формула, шкалы, тиры и значки — ровно как в требованиях; меняются только с согласия владельца.
  - Часть без данных — 0 очков с пометкой «нет данных».
  - Место: Score по убыванию, затем PnL за 30 дней; при полном равенстве — по имени, только для постоянного порядка.
  - Значок «📡 В топе дня» — по отметке «в топе дня» в метриках.
  - При установке считает итог первого снимка, поэтому слой 1 показывает рейтинг без сбора.
- <b class="arch-screens">Экраны:</b> нет.
- <b class="arch-routes">Маршруты:</b> нет.
- <b class="arch-api">API:</b>
  - `score(metrics)` (выход: части с сырым значением, долей шкалы и очками; Score; тир; значки)
  - `rank(date)` (выход: пусто; считает и сохраняет итог снимка)
  - `ranking(date)` (выход: KOL с Score, тиром, значками и местом)
- **Вызывает:**
  - Снимки, чтобы взять метрики снимка.

#### Борд: показывает клиенту рейтинг и карточку KOL

- **Что делает:** собирает клиентскую страницу: бегущая строка, hero, пьедестал топ-3, лидерборд с поиском, сортировкой и фильтрами по тиру и значку, раздел «Как считается Arena Score», подвал с источниками и датами. Карточка KOL с разбором Score по частям, значками, кошельком, ссылкой на Solscan и ссылками на источники.
  - Отдаёт клиенту только публичные поля. Ставки, условия, заметки, контакты нашей команды, реферальные ссылки, гипотезы — никогда. Публичный канал KOL в Telegram — публичное поле.
  - Данные KOL старше 48 часов помечены «данные устарели».
  - Нет данных — «—» и причина.
  - Слоты страницы: «раздел сети», «раздел радара», «фильтр сети» (вкладка лидерборда), «изменение места» (в строке), «дополнительные значки» (в строке и карточке), «дуэль дня» (в hero), «разделы ниже боя».
  - API-слот «в сети?»: отвечает, входит ли KOL в нашу сеть. Без заполнителя — нет.
  - Ставит на свою страницу виджеты KOL Fight: «В бой» в строках и карточке, «выбор бойцов» в разделе боя.
- <b class="arch-screens">Экраны:</b>
  - `главная` (рейтинг и разделы страницы) <span class="arch-tag">#public</span>. Детали: бегущая строка, плашка статистики, пьедестал, строка лидерборда, значок тира, полоса Score, пиксельный аватар.
  - `карточка KOL` (все метрики и разбор Score) <span class="arch-tag">#public</span>. Детали: диалог, разбор Score, сумма, кнопка «Скопировать».
- <b class="arch-routes">Маршруты:</b>
  - `GET /api/board?date=` (вход: дата снимка или последняя; выход: строки рейтинга, статистика hero, бегущая строка) <span class="arch-tag">#public</span>
  - `GET /api/kol/:id?date=` (выход: карточка KOL) <span class="arch-tag">#public</span>
- <b class="arch-api">API:</b> нет. Только люди.
- **Вызывает:**
  - Реестр KOL, чтобы взять профили.
  - Снимки, чтобы взять метрики, источники и даты.
  - Arena Score, чтобы взять Score, разбор, тир, значки и место.
- **На экранах:** [Главная](#sec-главная), [Карточка KOL](#sec-карточка-kol).

#### KOL Fight: проводит бой и делится им

- **Что делает:** выбор от 2 до 4 бойцов с поиском и быстрыми кнопками («Случайный бой», «#1 vs #2», «Реванш»). Проводит восемь раундов по правилам требований на одном снимке. Окно боя: экран VS, раунды по одному с «что меряем и почему» и «почему победил», урон, финал K.O. со счётом и сводкой, блок «Откуда Score». Ссылка на бой и картинка для X.
  - Бой всегда считается на одном снимке. Ссылка хранит снимок, поэтому ссылка и картинка совпадают. «Реванш на свежих данных» берёт последний снимок.
  - Раунд, где у кого-то нет данных, не засчитан. Ничья делит раунд. Раунд, где победили все, не засчитан никому. Равный счёт — побеждает тот, у кого выше Score.
  - В финале написано, сколько раундов засчитано.
  - Окно: фокус внутри, Esc закрывает, итоги раундов объявляются скринридеру, без анимации, если она отключена в системе.
  - Виджет «В бой»: кнопка, которая добавляет KOL в бой; её ставят Борд и Раздел сети.
  - Слот «перед боем» на экране VS.
  - События страницы: «боец добавлен» (id KOL), «бой окончен» (id бойцов, снимок, победитель).
- <b class="arch-screens">Экраны:</b>
  - `выбор бойцов` (слоты бойцов и быстрые кнопки) <span class="arch-tag">#public</span>. Детали: поле поиска, пиксельный аватар, кнопка.
  - `окно боя` (VS, раунды, финал, «Откуда Score») <span class="arch-tag">#public</span>. Детали: диалог, полоса HP, строка раунда, разбор Score.
- <b class="arch-routes">Маршруты:</b>
  - `GET /api/fight?ids=&date=` (выход: раунды, урон, победитель, сводка, разбор Score бойцов; у каждого значения источник и время получения) <span class="arch-tag">#public</span>
  - `GET /api/fight/image?ids=&date=` (выход: картинка результата для X) <span class="arch-tag">#public</span>
  - `GET /fight?ids=&date=` (выход: страница боя с превью для X) <span class="arch-tag">#public</span>
- <b class="arch-api">API:</b>
  - `fight(ids, date)` (выход: тот же результат, что в маршруте)
- **Вызывает:**
  - Снимки, чтобы взять метрики бойцов.
  - Arena Score, чтобы взять Score и разбор.
  - Реестр KOL, чтобы взять имена и аватары.
- **На экранах:** [Главная](#sec-главная), [Окно боя](#sec-окно-боя).

### 2. Ежедневные данные

Даёт свежий снимок каждый день без ручной работы и раздел «На радаре».

#### Сбор KOL Explorer: читает страницу лидеров KOL Explorer

- **Что делает:** раз в сутки читает публичную страницу лидеров KOL Explorer (150 KOL): кошелёк, хэндл X, PnL за день, 7 и 30 дней, нереализованный PnL, win rate за 7 и 30 дней, сделки, время последней сделки. Затем читает страницу профиля каждого KOL топ-100 ради средней позиции и медианного холда. Пишет топ-100 в снимок и хранит список «кошелёк — хэндл X» последнего чтения.
  - Страница изменилась (меньше 50 строк или нет нужных полей) — сбор считается неудачным, в снимок не пишется ничего.
  - Страница лидеров — один раз в сутки; профили — по одному с паузой в несколько секунд; всё с кэшем.
  - Профиль не прочитался — средняя позиция и холд этого KOL пустые, остальное пишется.
- <b class="arch-screens">Экраны:</b> нет.
- <b class="arch-routes">Маршруты:</b> нет.
- <b class="arch-api">API:</b>
  - `run(date)` (выход: итог — успех или ошибка, число строк)
  - `wallet_by_handle(x)` (выход: кошелёк или ничего)
- **Вызывает:**
  - Реестр KOL, чтобы завести KOL топа и опубликовать их кошельки с источником KOL Explorer.
  - Снимки, чтобы записать метрики и участников топ-100.

#### Сбор Solana Tracker: читает API Solana Tracker

- **Что делает:** раз в сутки через официальный API с ключом компании получает PnL за 7 и 30 дней, нереализованный и итоговый PnL, win rate за всё время, среднюю покупку, объём, дни со сделками, сделки в плюс и в минус, время последней сделки для KOL с опубликованным кошельком, которых нет в топе KOL Explorer. Получает список KOL дня с хэндлами X; ставит в снимке отметку «в топе дня».
  - Ключ — в настройке сервера, не в коде.
  - Отказ по ключу, лимиту или плану — сбор по этому KOL неудачный, его прошлые цифры остаются. Отказ из-за плана виден в состоянии сбора.
  - Не больше 3 запросов в секунду; около 2 200 запросов в месяц.
- <b class="arch-screens">Экраны:</b> нет.
- <b class="arch-routes">Маршруты:</b> нет.
- <b class="arch-api">API:</b>
  - `run(date)` (выход: итог по каждому KOL)
  - `kol_list(date)` (выход: KOL дня с хэндлами X и кошельками)
  - `wallet_by_handle(x)` (выход: кошелёк или ничего)
  - `wallet_summary(address)` (выход: есть ли сделки и время последней)
- **Вызывает:**
  - Реестр KOL, чтобы взять KOL с опубликованными кошельками.
  - Снимки, чтобы записать метрики и отметку «в топе дня».

#### Расписание сбора: запускает сбор и хранит итоги

- **Что делает:** каждый день в 06:00 UTC открывает снимок, отправляет событие «снимок открыт», запускает сбор KOL Explorer, затем Solana Tracker, закрывает снимок и затем просит Arena Score посчитать итог. Итог считается по закрытому снимку, вместе с перенесёнными метриками. Хранит итог каждого запуска по каждому источнику: время, успех или ошибка, число строк, текст ошибки. Администратор может запустить сбор вручную.
  - Два запуска одновременно невозможны.
  - Событие «снимок открыт» (дата) — другие блоки добавляют в снимок своих участников до сбора.
  - Слот экрана «другие источники» на экране состояния сбора: блоки выше показывают там итоги своих чтений. Без заполнителя пусто.
  - «Запустить сейчас» нужен, чтобы перезапустить сбор после сбоя источника.
- <b class="arch-screens">Экраны:</b>
  - `состояние сбора` (последний удачный сбор по источникам, ошибки, кнопка «Запустить сейчас») <span class="arch-tag">#staff</span>. Детали: список, значок состояния, кнопка.
- <b class="arch-routes">Маршруты:</b>
  - `GET /api/admin/collection` (выход: итоги запусков) <span class="arch-tag">#staff</span>
  - `POST /api/admin/collection/run` (выход: итог запуска) <span class="arch-tag">#admin</span>
- <b class="arch-api">API:</b> нет. Только люди и задача по расписанию.
- **Вызывает:**
  - Снимки, чтобы открыть и закрыть снимок.
  - Сбор KOL Explorer и Сбор Solana Tracker, чтобы собрать метрики.
  - Arena Score, чтобы посчитать итог снимка.
  - Журнал, чтобы записать ручной запуск.
- **На экранах:** [Состояние сбора](#sec-состояние-сбора).

### 3. Наша сеть

Даёт сеть со ставками, кошельки сети со статусами, раздел сети для клиента и подбор KOL под клиента.

#### Состав сети: читает таблицу сети и хранит ставки

- **Что делает:** раз в сутки, в 05:45 UTC, и по кнопке читает Google-таблицу владельца: имя, группа, ставки «от» и «до», условия, хэндл FOMO, pump.fun. Хранит участников сети, проверенный хэндл X, форматы работы, охват. Заводит KOL сети в Реестре. На событие «снимок открыт» добавляет в снимок KOL сети с опубликованным кошельком. Отвечает на API-слот Борда «в сети?».
  - Таблица — главный список. Строка пропала — KOL выходит из сети, история остаётся.
  - 9 KOL сети прототипа, которых нет в таблице, остаются в сети по решению владельца; чтение таблицы их не удаляет.
  - Заполняет слот «другие источники» на экране состояния сбора: время и итог последнего чтения таблицы.
  - «Прочитать таблицу сейчас» нужен, чтобы новый KOL из таблицы появился без ожидания суток.
  - Таблица не прочиталась или изменились колонки — состав не меняется, сбор неудачный.
  - Группа, ставки, условия и заметки видны только в закрытом разделе.
  - Адрес таблицы — в настройке сервера, не в коде.
  - Слот экрана «статус кошелька» в строке участника; без заполнителя пусто.
- <b class="arch-screens">Экраны:</b>
  - `сеть` (участники, ставки, проверка хэндла X, форматы, охват) <span class="arch-tag">#staff</span>. Детали: список, поле, кнопка.
- <b class="arch-routes">Маршруты:</b>
  - `GET /api/admin/network` (выход: участники со ставками) <span class="arch-tag">#staff</span>
  - `PATCH /api/admin/network/:kol` (вход: хэндл X, форматы, охват; выход: участник) <span class="arch-tag">#staff</span>
  - `GET /api/admin/network/export` (выход: файл со ставками) <span class="arch-tag">#staff</span>
  - `POST /api/admin/network/sync` (выход: итог чтения таблицы) <span class="arch-tag">#admin</span>
- <b class="arch-api">API:</b>
  - `members()` (выход: участники без ставок)
  - `is_member(kol)` (выход: да или нет)
  - `verified_handle(kol)` (выход: хэндл X и проверен ли он)
  - `rates(kols)` (выход: ставки и форматы) — только для блоков с маршрутами `#staff`
- **Вызывает:**
  - Реестр KOL, чтобы завести KOL сети, записать форматы и охват.
  - Снимки, чтобы добавить KOL сети в снимок.
  - Журнал, чтобы записать каждое изменение.
- **На экранах:** [Сеть](#sec-сеть).

#### Кошельки сети: ищут и подтверждают кошельки KOL сети

- **Что делает:** заполняет слот «статус кошелька» на экране Сети. Хранит для каждого KOL сети кошельки-кандидаты со статусом (подтверждён, гипотеза, не найден), источником, доказательством, тем, кто прислал адрес, и временем. После чтения таблицы ищет кошельки по хэндлу X в KOL Explorer и Solana Tracker. Подтверждённые кошельки публикует в Реестр.
  - Совпал проверенный хэндл X — подтверждён. Непроверенный хэндл или только имя — гипотеза; после проверки хэндла подтверждается сам.
  - Адрес от KOL подтверждается после проверки, что по кошельку есть сделки.
  - Гипотеза никогда не публикуется.
  - Каждое изменение статуса записывается в Журнал.
  - Видно, сколько KOL в каждом статусе.
- <b class="arch-screens">Экраны:</b>
  - `кошельки` (статусы, счётчики, подтвердить, отклонить, добавить адрес от KOL, выбрать основной) <span class="arch-tag">#staff</span>. Детали: список, значок статуса, диалог.
- <b class="arch-routes">Маршруты:</b>
  - `GET /api/admin/wallets` (выход: кандидаты и счётчики) <span class="arch-tag">#staff</span>
  - `POST /api/admin/wallets` (вход: KOL, адрес, кто прислал; выход: кандидат) <span class="arch-tag">#staff</span>
  - `POST /api/admin/wallets/:id/confirm`, `/reject`, `/main` (выход: кандидат) <span class="arch-tag">#staff</span>
- <b class="arch-api">API:</b>
  - `propose(kol, address, evidence)` (выход: гипотеза)
  - `status(kol)` (выход: статус без адреса гипотезы)
- **Вызывает:**
  - Состав сети, чтобы взять участников и проверенные хэндлы.
  - Сбор KOL Explorer и Сбор Solana Tracker, чтобы найти кошелёк по хэндлу и проверить сделки.
  - Реестр KOL, чтобы опубликовать подтверждённые кошельки.
  - Журнал, чтобы записать изменения.
- **На экранах:** [Кошельки](#sec-кошельки).

#### Сверка по FOMO: находит кошелёк по позициям из профиля

- **Что делает:** сотрудник вносит 2–3 позиции из профиля KOL на FOMO: адрес токена и количество. Блок находит через публичный узел Solana держателей каждого токена с тем же количеством, с допуском на округление, и пересекает списки. Подходит ровно один кошелёк и совпали минимум 2 позиции — предлагает гипотезу в Кошельки сети.
  - Профиль FOMO читает только человек; блок FOMO не открывает.
  - Узел не ответил или держателей слишком много — ошибка с объяснением, гипотезы нет.
- <b class="arch-screens">Экраны:</b>

- <b class="arch-routes">Маршруты:</b>
  - `POST /api/admin/fomo-match` (вход: KOL, позиции; выход: кандидаты по каждой позиции и общий итог) <span class="arch-tag">#staff</span>
- <b class="arch-api">API:</b> нет. Только люди.
- **Вызывает:**
  - Кошельки сети, чтобы предложить гипотезу.
  - Журнал, чтобы записать сверку.
- **На экранах:** [Сверка FOMO](#sec-сверка-fomo).

#### Раздел сети: показывает клиенту KOL нашей сети

## 4. Экраны и формы

У каждого экрана один владелец; блоки того же или более высоких слоёв заполняют его слоты или ставят свои виджеты. Рамку каждой страницы даёт [веб-оболочка](#sec-веб-оболочка-обрамляет-каждую-страницу). Тексты клиентской страницы — на английском.

### Клиентская страница

#### Главная

- **Адрес:** `/`. **Владелец:** [Борд](#sec-борд-показывает-клиенту-рейтинг-и-карточку-kol), `главная`.
- **Расположение сверху вниз:**
  - Бегущая строка: #1 по Score, лучшие за неделю, сколько KOL торговали за час, сколько в плюсе за месяц ([Борд](#sec-борд-показывает-клиенту-рейтинг-и-карточку-kol)); «Взлёт недели» ([Изменение места](#sec-изменение-места-показывает-рост-и-падение-kol)); лучший из сети ([Состав сети](#sec-состав-сети-читает-таблицу-сети-и-хранит-ставки) через слот «в сети?»).
  - Hero: KOL ARENA, «Only N of M tracked KOLs are up over 30 days», четыре плашки статистики ([Борд](#sec-борд-показывает-клиенту-рейтинг-и-карточку-kol)); дуэль дня ([Дуэль дня](#sec-дуэль-дня-выбирает-бой-на-день)).
  - Пьедестал топ-3 ([Борд](#sec-борд-показывает-клиенту-рейтинг-и-карточку-kol)).
  - Лидерборд: вкладки «All / Top-100 / 🤝 Our network» ([Раздел сети](#sec-раздел-сети-показывает-клиенту-kol-нашей-сети) даёт третью), поиск, сортировка, фильтры; строки с местом и стрелкой ([Изменение места](#sec-изменение-места-показывает-рост-и-падение-kol)), значками серий ([Серии](#sec-серии-дают-значки-за-серии)) и кнопкой «В бой» ([KOL Fight](#sec-kol-fight-проводит-бой-и-делится-им)). На телефоне строки становятся карточками.
  - «Our network» ([Раздел сети](#sec-раздел-сети-показывает-клиенту-kol-нашей-сети)).
  - KOL Fight: выбор бойцов ([KOL Fight](#sec-kol-fight-проводит-бой-и-делится-им)).
  - Турнир ([Турнир](#sec-турнир-проводит-сетку-на-8-kol)).
  - «On the radar» ([На радаре](#sec-на-радаре-показывает-kol-дня-которых-нет-на-борде)).
  - «How Arena Score works»: четыре части с весами и шкалами, тиры, значки, источники с датами снимков ([Борд](#sec-борд-показывает-клиенту-рейтинг-и-карточку-kol)).
  - Подвал: источники, даты, NFA · DYOR ([Борд](#sec-борд-показывает-клиенту-рейтинг-и-карточку-kol)).
- **Формы:** поиск по имени и хэндлу X; сортировка; фильтры по тиру и значку; выбор бойцов.

#### Карточка KOL

- **Адрес:** `/kol/:id`, поверх главной. **Владелец:** [Борд](#sec-борд-показывает-клиенту-рейтинг-и-карточку-kol), `карточка KOL`.
- **Расположение:** шапка — имя, хэндл X, тир, значок «сеть», место; Score и все метрики; разбор Score по четырём частям; значки с объяснением, включая серии ([Серии](#sec-серии-дают-значки-за-серии)); форматы работы; кошелёк с «Copy» и ссылкой на Solscan; ссылки на X, KOL Explorer или Solana Tracker, Kolscan, FOMO, pump.fun, канал KOL в Telegram; источник и дата снимка; кнопка «В бой» ([KOL Fight](#sec-kol-fight-проводит-бой-и-делится-им)).

#### Окно боя

- **Адрес:** `/fight?ids=…&date=…`, поверх главной; на телефоне во весь экран. **Владелец:** [KOL Fight](#sec-kol-fight-проводит-бой-и-делится-им), `окно боя`.
- **Расположение:** экран VS с аватарами, тирами, Score и полосами HP; выбор «кто победит» ([Угадай победителя](#sec-угадай-победителя-даёт-угадать-исход-боя)); раунды по одному; финал K.O.; вкладка «Where Score comes from»; кнопки «Rematch», «Rematch on fresh data», «Change fighter», «Share», «Open card».
- **Формы:** «Next», «Skip animation», выбор победителя до боя.

### Закрытый раздел

Адреса начинаются с `/team`. Без входа открывается только экран входа.

#### Вход

- **Адрес:** `/team/login`. **Владелец:** [Вход](#sec-вход-пускает-сотрудников-в-закрытый-раздел), `вход`.
- **Формы:** логин, пароль, «Войти».

#### Сотрудники

- **Адрес:** `/team/staff`. **Владелец:** [Вход](#sec-вход-пускает-сотрудников-в-закрытый-раздел), `сотрудники`.
- **Формы:** добавить сотрудника (логин, роль, временный пароль); отозвать доступ.

#### Сеть

- **Адрес:** `/team/network`. **Владелец:** [Состав сети](#sec-состав-сети-читает-таблицу-сети-и-хранит-ставки), `сеть`.
- **Расположение:** список участников со ставками и группой, статус кошелька в слоте «статус кошелька» ([Кошельки сети](#sec-кошельки-сети-ищут-и-подтверждают-кошельки-kol-сети)), дата чтения таблицы.
- **Формы:** проверить хэндл X; форматы; охват с источником и датой; «Выгрузить со ставками»; «Прочитать таблицу сейчас».

#### Кошельки

- **Адрес:** `/team/wallets`. **Владелец:** [Кошельки сети](#sec-кошельки-сети-ищут-и-подтверждают-кошельки-kol-сети), `кошельки`.
- **Расположение:** счётчики по статусам; список KOL сети с кандидатами, источником, доказательством и историей изменений.
- **Формы:** добавить адрес от KOL (адрес, кто прислал); подтвердить; отклонить; сделать основным.

#### Сверка FOMO

- **Адрес:** `/team/fomo`. **Владелец:** [Сверка по FOMO](#sec-сверка-по-fomo-находит-кошелёк-по-позициям-из-профиля), `сверка FOMO`.
- **Формы:** KOL; 2–3 строки «адрес токена, количество»; «Найти»; «Предложить гипотезу».

#### Подбор

- **Адрес:** `/team/picker`. **Владелец:** [Подбор](#sec-подбор-собирает-kol-сети-под-клиента), `подбор`.
- **Формы:** Score от и до, тир, ставка от и до, формат; отметки KOL; «Выгрузить для клиента» и «Выгрузить со ставками».

#### Состояние сбора

- **Адрес:** `/team/collection`. **Владелец:** [Расписание сбора](#sec-расписание-сбора-запускает-сбор-и-хранит-итоги), `состояние сбора`.
- **Расположение:** по каждому источнику (KOL Explorer, Solana Tracker) — последний удачный сбор, последняя ошибка, число строк; запуски по дням; итог чтения таблицы сети в слоте «другие источники» ([Состав сети](#sec-состав-сети-читает-таблицу-сети-и-хранит-ставки)).
- **Формы:** «Запустить сейчас» (администратор).

## 5. Платформа и сборка

Не бизнес-компоненты. Не хранят бизнес-данных и правил, не называют ни одного блока.

### Сборка

- Теги аудитории: `public`, `staff`, `admin`. Страницы `public` открываются без входа. Администратор имеет всё, что есть у сотрудника.
- Приложение — сервер и оболочка с набором плагинов и тегов:
  - Клиентская страница [public].
  - Закрытый раздел [public, staff, admin]: только экран входа открыт без входа.
- Оба приложения работают на одном сервере и одном адресе сайта.
- Адреса страниц берут теги своих экранов: `/`, `/kol/:id` и `/fight` — public; `/team/login` — public; остальные `/team/…` — staff, `/team/staff` — admin. Закрытый адрес без входа ведёт на `/team/login`.

#### Сервер: запускает все блоки одной программой

- Программа на Rust. Находит плагины и запускает миграции каждого. Как приложение — подключает маршруты тегов, которые оно обслуживает. Как исполнитель — запускает задачи по расписанию.
- Настройки сервера, не в коде: ключ Solana Tracker, адрес таблицы сети, первый администратор.

#### Веб-оболочка: обрамляет каждую страницу

- Меню, раскладка, адреса страниц. Подключает экраны тегов, которые обслуживает приложение. Соединяет слоты и виджеты по имени и тегу.
- Рамка каждой страницы: верхняя панель с меню и плавающие места. Блоки ставят туда свои виджеты.
- Тексты страницы — в одном словаре, чтобы позже добавить русский язык.

### Платформа

Нужна каждому блоку.

- **Сервер:** пул базы, запуск миграций, очередь задач и расписание, реестр тегов, журналы работы.
- **Человек запроса:** слот, который говорит, от чьего имени идёт запрос. Его заполняет [Вход](#sec-вход-пускает-сотрудников-в-закрытый-раздел). Без заполнителя — никто, поэтому работают только маршруты `public`.
- **Реестр реализаций:** выбирает реализацию на каждый вызов, для испытаний и сравнения; выбирает «выключено» для заглушки по приложению, группе или человеку.

#### Дизайн-система: даёт каждому экрану его вид

- **Правила:**
  - Экраны блока пользуются только деталями дизайн-системы. Ни у одного блока нет своих цветов или кнопок.
  - Деталь показывает только то, что ей передал вызывающий. Она никогда не вызывает маршрут.
  - Детали не импортируют блоки. Сборка падает, если импортируют.
  - Новая общая потребность добавляется сюда, а не копируется в блок.
  - Одна страница показывает все детали.
  - Каждая деталь работает от 360 px без горизонтальной прокрутки и с клавиатуры.
- **Правила вида:** стиль прототипа — аркадный автомат для трейдеров. Фон `#110d1c`, панели `#1a1430`; акценты: монета `#ffc93c`, неон-розовый `#ff4d8d`, голубой `#6cc6ff`, лавандовый `#b79cff`, плюс `#2fe5a7`, минус `#ff7062`. Шрифты: Press Start 2P для заголовков, Golos Text для текста, JetBrains Mono для цифр. Жёсткие тени. Без анимации, если она отключена в системе. Хранятся общими значениями в коде.
- **Базовые детали:** кнопка, поле, список, карточка, диалог, вкладки, значок, полоса прогресса.
- **Детали KOL Arena:** общие виды со смыслом в KOL Arena, без данных.

##### Пиксельный аватар

Аватар-спрайт KOL, одинаковый для одного id.

##### Значок тира

GOAT, Diamond, Sendoor или Degen со своим цветом и иконкой.

##### Полоса Score

Score от 0 до 100 полосой и числом.

##### Сумма

Деньги в долларах: зелёный плюс, красный минус, «—» при отсутствии данных с подсказкой причины.

##### Разбор Score

Четыре части: сырое значение, доля шкалы, очки; часть без данных подписана «no data».

##### Бегущая строка

Строка новостей арены, без анимации, если она отключена в системе.

##### Полоса HP

Здоровье бойца в бою, убывает с уроном.

##### Строка раунда

Название раунда, «что меряем», значения бойцов с полосами, победитель или «void», фраза «почему».

##### Сетка турнира

Восемь участников, четвертьфиналы, полуфиналы, финал.
